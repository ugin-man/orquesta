# Orquesta V4 Desktop 0.4.0-preview.1

Status: public preview

This candidate packages the current V4 product line for public review. It intentionally excludes V5 Phase 1 development, internal review workbenches, raw Orquesta runtime state, and the unpublished demo video.

## Included

- Windows x64 Orquesta Desktop with project intake, resumable setup, organization map, records, user tasks, settings, project switching, and Luca explanations.
- The canonical Orquesta Codex skill and V4 runtime modules.
- File-backed delegation, evidence, acceptance, context routing, session rotation, and execution-kernel paths that belong to V4.
- The reproducible V4 product benchmark harness and its source/license record.
- Public documentation with personal local paths and live session identifiers replaced by synthetic examples.

## Known limits

- Windows x64 only and no code signing or automatic updater.
- The project owner authorized publication of the startup brand image; its transparent artwork was verified on the warm startup canvas.
- Production dependency audits were clean on 2026-08-07, while the Desktop development/build tree retained disclosed transitive findings described in `SECURITY.md`.
- Historical Build Week and design documents are provenance, not current acceptance evidence.
- The published Windows assets are unsigned preview builds, so Windows may display a warning before launch.

## Upgrade notes

- Do not delete a managed project's `.orquesta/` directory when updating the app or skill. It contains project-owned state and evidence.
- Back up or copy an existing managed project before its first run with this preview.
- Reinstall the canonical skill with `scripts/sync-orquesta-skill.js`; do not merge old skill files by hand.
- V5 development state and code are not migration inputs for this V4 release.

## Verification boundary

Focused repository checks, benchmark checks, Desktop unit/build checks, package audits, and local packaged-runtime checks passed before publication. These checks do not replace independent clean-download and end-user workflow evidence.

Independent testers can use the [Moltbook AI preview test](../testing/moltbook-ai-preview-test.md). It keeps reading feedback separate from actual execution evidence and uses a disposable fictional support-triage fixture.
