# 常設担当を追加する

この手順は、統括者が常設の担当を増やしたい時だけ読む。P2ではDesktop操作担当として利用者支援係がこの限定操作を担うが、他のDesktop操作や常時監視まで役割を広げない。別のDesktop操作や一時担当には使わない。

## 分担

統括者は、必要な担当の目的と背景を自然な言葉で利用者支援係へ渡す。利用者支援係は同じDirectoryの`organization-agent-placement-persistent-v1.schema.json`だけを読み、次の意味を正規化してTemplateへ記入する。

- 何を担当するか
- 必要な能力
- 現在のRole正本に存在する正確な役職IDと版
- 所属するProject、Line、またはTeamの正確なID
- 必要人数
- 複数人の場合の連携方法

ID、時刻、revision、hash、保存Path、Task ID、Agent IDは書かない。これらはDesktop Controllerが付与する。

## 情報が足りない時

推測で欄を埋めない。Compilerから意味の不足や候補の曖昧さが返った時は、issuesにある不足項目、理由、候補だけを統括者へ返す。統括者の補足を受けてTemplateを修正し、もう一度渡す。未修正の同じTemplateを自動再送しない。

型違い、余計な欄、並びや表記の不正など、意味ではなくTemplateの作り方に問題がある時は統括者へ質問しない。利用者支援係へ戻し、この手順とSchemaに沿って出力だけを修正する。「三人」を文字列のまま残した場合もこの扱いにする。意味が特定できない状態を、書式修正のふりをして埋めてはいけない。

利用者支援係が表記を理解できる場合は、意味を変えずに正規化する。例えば「三人」は`requested_count: 3`へ直せる。一方で、どのLineを指すか複数候補がある場合や必要能力を特定できない場合は、勝手に選ばず統括者へ返す。

## 完成条件

TemplateがSchemaに一致し、能力とScopeが現在の正本に正確に存在し、Controllerが受付可能と判定した時だけ書き込みへ進む。受付後の採番、検算、保存、再送時の重複防止はDesktop Controllerが担う。
